**Context, Concurrency, and Processes**

- Thread `context.Context` through long-running, subprocess, and networked work; prefer `exec.CommandContext`; use derived contexts and timeouts for cleanup and HTTP calls.
- Route every long-lived subprocess spawned for a cancellable step or agent invocation through the appropriate `shellenv` lifecycle configurator. Agents and other subprocesses use `ConfigureShellCommand`: it creates a process-tree boundary and installs `cmd.Cancel` to kill the whole tree, so grandchildren (test workers, build watchers) cannot outlive cancellation and hold the next run's worktree locked. Repository `commands.*` and custom gates use `ConfigureCooperativeShellCommand`: on Windows it sends targeted `CTRL_BREAK`, preserves up to a three-second cleanup window, then retains the same forced Job Object fallback. Regressions: `TestConfigureCooperativeShellCommandCancelAllowsCleanup`, `TestConfigureCooperativeShellCommandCancelForcesNonCooperatingTree`.
- `cmd.Cancel` covers only cancellation; on clean exit or error the group is not reaped, and leaked grandchildren accumulate until the OS OOM-kills the daemon (surfacing as `daemon crashed during execution` with no stack trace). Use `shellenv.RunShellCommand` / `OutputShellCommand` / `CombinedOutputShellCommand` for one-shot commands, or `StartShellCommand` plus `TerminateShellCommandGroup` when handling pipes manually; the helper doc comments in `internal/shellenv` own the details. `ConfigureShellCommand` also installs a 5s `cmd.WaitDelay` backstop so a grandchild holding an inherited pipe cannot wedge `cmd.Wait` forever. Regressions: `TestCodexAgent_Run_ReapsLeakedGrandchildOnCleanExit`, `TestRunShellCommandWithEnv_ReapsGrandchildOnCleanExit`, `TestTerminateShellCommandGroup_*`.
- A process group is not a sandbox: a child can escape it with `setsid` or `setpgid`. Every run-owned command must also use its run supervisor (`ConfigureShellCommandForContext`, or `ConfigureShellCommand` plus `SuperviseShellCommand`) and start through the shellenv boundary, which stamps `RunIDEnvVar`. Managed servers apply the same marker at their launch boundary. Linux cleanup matches that exact inherited marker, never cwd or ancestry, so escapees that chdir away are still owned and unmarked shells/editors remain untouched. Windows job objects contain the tree; macOS cannot guarantee reaping escaped groups. Production startup/eject use `procreap.SweepMarkedRunWorktrees`, not the legacy cwd classifier. `internal/shellenv/run_supervisor.go` owns the contract; regressions include `TestRunCleanupSparesForeignProcessInWorktree`, `TestRunCleanupReapsEscapedProcessThatLeftTheWorktree`, and `TestStartServerWithPort_StampsRunMarkerIntoServerEnvironment`.
- On Windows the daemon runs console-less, so route every console child through `winproc.Harden(cmd)` (no-op elsewhere, idempotent, preserves existing creation flags) or a console window flashes per child (#287). `shellenv.ConfigureShellCommand` already calls it; one-shot commands built directly must call it themselves. Regressions: `TestHarden*` in `internal/winproc`.
- Protect shared mutable state with the standard sync/atomic tools, and be explicit about ownership and cleanup of goroutines, worktrees, temp dirs, and channels.
